# status.md — 「わからない」の5分類

## なぜ厳密に分けるのか

「不明」で一括りにすると、**次に何をすればよいかの情報が消える**。
非公表なら諦めて代替指標を設計する、未調査なら時間を使えば埋まる、調査不可ならユーザに頼めば埋まる。
判断への影響度も違う（非公表は構造的な情報格差、未調査は自分の手落ち）。

**特に「未調査」と「未特定」の区別が重要。** 前者は手を付けていない、
後者は探索を尽くしたが確認できなかった、という全く別の状態を指す。
これを混同すると「調べていないこと」が「存在しないこと」として扱われる。

## 判定フロー

```
その項目について、
├─ 情報源を特定できたか？
│   ├─ No → 探し方は尽くしたか？（飽和条件・search_log.jsonl）
│   │        ├─ Yes かつ「開示義務が無い/存在しない」と確認できた → [非公表]
│   │        ├─ Yes だが存在有無すら判断できない          → [未特定]
│   │        └─ No（そもそも探索していない）              → [未調査]
│   └─ Yes → その情報源に到達できたか？
│            ├─ No（有料/ログイン/取得失敗/言語/紙のみ） → [調査不可] ＋ 依頼発行
│            └─ Yes → 該当記載があったか？
│                     ├─ Yes → 事実として台帳へ（ステータス不要）
│                     └─ No  → [非公表]（negative証拠を台帳に登録）
```

**`[非公表]`と`[未特定]`の分かれ目**: 「その文書に載っていないことを確認した」なら
非公表（negative証拠が取れる）。「探したが、載っているのかどうかすら分からない」なら
未特定（飽和条件の記録で裏付ける）。

数値を「持っていないが計算・類推はできる」場合は、上記のどれでもなく `[推定]` を使う。
**推定を事実欄に混ぜない**こと。混ざった瞬間に、後で誰も切り分けられなくなる。

## 各ステータスの成立条件と書式

### `[非公表]`
成立条件: **negative証拠E-IDが1つ以上**。
書式: `セグメント別の設備投資額 [非公表|確認:E-0042(有報 設備の状況)|代替:全社CAPEXとセグメント売上比で按分→F-05]`
- 「開示義務が無い項目」なのか「あるはずだが載っていない」のかを `note` に区別して書く
- 必ず**代替アプローチ**を1つ添える。代替が無いなら結論への影響を書く

### `[未調査]`
成立条件: 次アクション＋想定ソース＋優先度。
書式: `海外子会社の従業員構成 [未調査|次:有報 従業員の状況を確認|優先:M]`
- スコープ外で意図的に見送ったものは `[未調査|意図的|理由:～]` と書く
  （手落ちと区別できるようにする。これが無いと次回の自己改善で誤った反省をする）

### `[調査不可]`
成立条件: 障壁コード＋依頼ID。
書式: `Q3決算説明会の質疑応答 [調査不可|PAYWALL|依頼:R-003]`

| コード | 意味 |
|---|---|
| `PAYWALL` | 有料課金が必要 |
| `LOGIN` | 会員登録・ログインが必要 |
| `PRICED_DB` | 有料DB（アナリストレポート、業界専門DB等） |
| `FETCH_FAIL` | 3回試行して取得失敗（403/JS必須/PDF破損等） |
| `NOTFOUND` | 存在するはずのURL・文書に到達できない |
| `LANG` | 言語・形式の制約（紙のみ、スキャン画質不良等） |

**3回試行ルール**: 取得失敗は、検索語を変える・別ドメイン（IRサイト直/開示システム）を試す・
キャッシュや別形式を試す、の3手を尽くしてから `FETCH_FAIL` にする。1回で諦めない。

### `[推定]`
成立条件: 根拠E-ID＋ロジック＋確信度＋反証条件。
書式: `26年3月期の粗利率は42〜44% [推定|根拠:E-0011,E-0019|ロジック:過去3期のミックス変化を直線外挿|確信度:中|反証:製品Aの単価下落が続く場合]`
- 確信度の目安 — 高: 複数T1〜T2証拠から機械的に導ける／中: 前提1〜2個を置く／低: 前提が3個以上、または外部環境依存
- **レンジで書く**。単一値の推定は事実と誤読される

### `[未特定]`

成立条件: **必要証拠リストの項目ID(N-xx)** ＋ **探索ログの飽和条件**。
書式: `セグメント別設備投資額 [未特定|対象:N-01]`

- 「未探索（手を付けていない）」とは別物。**探索を尽くした上で見つからなかった**ことを示す
- 飽和条件（`search_log.jsonl`で機械検証）: 直近3件が**経路もクエリも互いに異なり**、
  その3件全てで新規対象・新規事実が0件であること
- これは打ち切りを許可する**最低条件**。新規が出続ける限り探索を継続する
- 経路を分けても同一クエリを使い回すのは、飽和条件を満たさない（`references/workflow.md`「探索ログ」参照）
- Critical項目（`scope.md`で重要度C）をこれで閉じる場合のみ使う。Normal項目は`[未調査]`で足りる

## 誤用の典型

| NG | なぜダメか | 直し方 |
|---|---|---|
| 「情報が見つかりませんでした」 | 3分類のどれか不明。次アクションが決まらない | 判定フローを通す |
| 探さずに `[非公表]` | negative証拠が無い。実は開示されている可能性 | `[未調査]` にする |
| `[調査不可]` で終わらせる | ユーザなら取得できる場合がある | 依頼を必ず発行 |
| 推定値を表に素の数字で入れる | 後工程で事実として再利用される | セル内に `[推定]` を残す |
| 探索ログ無しで `[未特定]` を書く | 「未探索」と区別できず、探索の裏付けが無い | `search_log.jsonl`に直近3件を記録してから書く |
| `[未調査]` を最終レポートに大量に残す | 調査の未完成を示す | 上位3件に絞り、残りは付録へ。スコープ外は意図的と明記 |
