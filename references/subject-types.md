# subject-types.md — 調査対象別の型

## この文書は何か

同じ検証機構（証拠台帳・Wチェック・ステータス語彙・ゲート）の上で、
**調査対象によって変わる3つの型**だけをここに置く。

| 対象 | 使う場面 |
|---|---|
| 企業 | 対象企業が決まっており、その企業を深掘りする（既定） |
| 技術 | 個別企業に入る前に、特定技術そのものの理解を深める（先行調査） |
| 業界 | 個別企業に入る前に、業界構造の理解を深める（先行調査） |

**変わるのは「必要証拠リストの型」「図解の型」「問い」の3つだけ。**
中核ルール・台帳の書き方・Wチェック・ゲート・レポート様式は対象を問わず共通で、
対象別に緩めたり省略したりしない。

P0で対象の種別を決め、`scope.md` の冒頭に `対象種別: 企業 / 技術 / 業界` を記録する。

---

## 先行調査（技術・業界）の位置づけ

**やること**: 個別企業に入る前に、その技術・業界そのものを理解する。
成果物は独立したレポートとして出してよい。

**やらないこと**: 候補企業を広く探して絞り込む（スクリーニング）。
これは SKILL.md 適用範囲の通り本ハーネスの範囲外で、証拠台帳の粒度に合わない。
先行調査で個別企業名が出てくるのは避けられないが、
**「主要プレイヤーの把握」と「投資候補の選定」は別物**として扱う。

### 先行調査から企業調査へ移るときの関門

先行調査の中で「この技術ではA社が先行している」と知ると、
次の企業調査の対象がその時点で事実上決まってしまうことがある。
しかもその決まり方は、最初にヒットした見栄えのする情報に引きずられている可能性がある
（I-101 の評価軸アンカリングと同じ構造）。

移行時に、次を `scope.md` に明記してから企業調査に入る:

- **なぜこの企業を対象に選んだか**（先行調査のどの発見が根拠か。E-IDで指す）
- **他に検討した候補と、外した理由**（検討していないなら「未検討」と書く。空欄にしない）
- **この選定が誤りだった場合に気づける条件**（何が観測されたら選定を見直すか）

「なんとなく最初に名前が出たから」で選んでいるなら、それを自覚するのがこの関門の目的。

## 企業（既定）

SKILL.md 本文の記述がそのまま適用される。以下は要約。

**必要証拠リストの型**: 事業構造・セグメント別業績・財務健全性・競争環境・
ガバナンス・リスク・株主還元。詳細は `references/questions.md` 共通コア。

**図解の必須セット**:
- F-01 収益分解ツリー（売上→セグメント→ドライバ）
- F-02 バリューチェーン内位置と競合マップ
- F-03 業績・指標時系列（最低5期、開示ベース）
- F-04 仮説→ドライバ→検証指標ツリー（各仮説に崩壊条件）
- F-05 リスク／感応度

**問い**: `references/questions.md` の共通コアから5〜10問（`Q-R4` は必須）。

## 技術

**何を明らかにするのか**: その技術が何を可能にし、何に制約され、
誰がその制約を握っているか。「すごい技術か」ではなく「どこが詰まるか」を問う。

### 必要証拠リストの型

| 区分 | 集めるもの | 想定ソース階層 |
|---|---|---|
| 技術の定義と原理 | その技術が解決する課題、従来手法との違い | T3（学会・標準化団体）／T2（開発元の技術資料） |
| 性能指標 | **その分野で優劣が何で語られるか**（複数軸）と各軸の現在値 | T3／T5（複数の独立した評価） |
| 採用・実装状況 | 実際に量産・実装されているか、試作段階か | T1（開示）／T2（発表）／T3（統計） |
| バリューチェーン | 材料→製造装置→デバイス→実装→最終製品 の各層と担い手 | T3（業界団体）／T5 |
| ボトルネック | どの層が供給制約・技術的難所になっているか | T3／T5 |
| 代替技術 | 競合する技術方式と、それぞれの得失 | T3／T5 |
| ロードマップ | 次世代で何が変わる見込みか、時期 | T2／T3（標準化ロードマップ） |

**性能指標の扱いは特に注意する（I-101 の再発防止）**:
評価軸を記憶から先に固定しない。「この分野で優劣は何を基準に語られているか」を
**複数ソースで調べてから**軸を確定し、その後で各軸の数値を集める。
軸を探す調査で「トレンドの動く速さ」も同時に分かるので、鮮度基準もそこで決める。

### 図解の型

- **T-01 技術バリューチェーン**: 材料→装置→デバイス→実装→最終製品。各層の担い手を併記
- **T-02 評価軸マップ**: その技術の優劣を測る複数軸と、主要方式の位置づけ
  （単一軸で優劣を描かない。軸ごとに勝者が違うことを可視化する）
- **T-03 性能・採用の時系列**: 主要指標の推移と、量産・採用の節目
- **T-04 ボトルネック図**: どの層が詰まっているか、その制約を握るのは誰か
- **T-05 代替技術の得失**: 競合方式との比較（各行にE-ID）

### 主な問い

- この技術は何を可能にし、従来の何を置き換えるか
- **この分野で優劣は何を基準に語られているか**（軸は調査で確定する）
- 各評価軸で、現在どの方式・どのプレイヤーが先行しているか
- 実際に量産・実装されているか、試作・研究段階か
- バリューチェーンのどの層が供給制約になっているか
- その制約を握っているのは誰か（迂回可能か、代替は効くか）
- 代替技術は何で、どういう条件でそちらが優位になるか
- 次世代で何が変わる見込みか、その時期の根拠は何か
- この技術トレンドはどの程度の速さで動くか（＝鮮度基準の根拠）

## 業界

**何を明らかにするのか**: その業界で誰が何を握り、利益がどこに落ち、
何がその構造を変えうるか。

### 必要証拠リストの型

| 区分 | 集めるもの | 想定ソース階層 |
|---|---|---|
| 市場規模と成長 | 規模・成長率・地域別内訳 | T3（公的統計・業界団体）必須 |
| バリューチェーン | 川上→川下の各層と、各層の担い手 | T3／T5 |
| 主要プレイヤー | 各層の主要企業とシェア | T3（第三者統計）／T1（開示） |
| 利益プール | どの層に利益が集中しているか（各層の利益率） | T1（各社開示）／T3 |
| 参入障壁 | 各層の参入難易度と、その源泉 | T3／T5 |
| 規制・政策 | 業界を規定する規制、補助、貿易措置 | T3（規制当局）必須 |
| 需要side | 誰が買い、何で選ぶか、代替は何か | T3／T5 |
| 構造変化 | 足元で何が変わりつつあるか、その駆動要因 | T3／T5 |

**市場規模・シェアは T3（第三者）で必ず裏を取る。**
発行体の自称（T2）だけに依存しない。これは SKILL.md ソース階層の原則そのまま。

### 図解の型

- **I-01 バリューチェーン**: 川上→川下の各層と担い手。層ごとの利益率を併記
- **I-02 主要プレイヤーマップ**: 各層の企業とシェア（出所を明記）
- **I-03 市場規模の時系列**: 規模・成長率の推移（T3ベース）
- **I-04 利益プール図**: どの層に利益が落ちているか
- **I-05 構造変化の駆動要因**: 何が業界構造を変えつつあるか、その影響先

### 主な問い

- この業界の市場規模と成長率はどれくらいか（第三者統計で確認したか）
- バリューチェーンはどう構成され、各層に誰がいるか
- **利益はどの層に落ちているか**（売上規模ではなく利益率で見る）
- 各層の参入障壁は何で、その源泉は何か（技術／規制／規模／顧客ロックイン）
- 誰が買い、何を基準に選んでいるか
- この業界を規定する規制・政策は何か、変更の兆しはあるか
- 足元で構造が変わりつつある箇所はどこか、その駆動要因は何か
- **顧客が迂回できない層はどこか**（SKILL.md「希少層」の考え方を業界全体に適用）

## 共通して守るもの（対象を問わない）

対象別に緩めてよいものは何もない。特に次は対象を問わず適用される。

- 原文がローカルに保存されていない情報は書けない（中核ルール1）
- すべての事実記述に E-ID。**台帳が無い状態で E-ID を書かない**（ROK案件の失敗）
- 検証はスクリプトが行う。実行痕跡（`checks/receipt_*.json`）が無ければ通っていない
- ステータス語彙（`[非公表]`『[未調査]』『[調査不可]』『[推定]』『[未特定]`）で書き分ける
- 図表のデータ行は全て E-ID を持つ（技術・業界の図解も同じ）
- ソース階層の上位を優先し、矛盾は消さず両論併記＋採用理由
